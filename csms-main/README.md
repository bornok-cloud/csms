# Kape't Kwento — Café Management System (Flutter Frontend)

A complete Flutter/Dart frontend for a café management system with Admin,
Employee, and Customer sides, built with mock/local data so every screen and
interaction can be demonstrated without a backend.

## How to run in Android Studio

This package contains the Flutter/Dart **source code** (`lib/`, `pubspec.yaml`).
It does not include the native `android/`, `ios/`, `web/` platform folders,
since those are auto-generated by the Flutter CLI and are best generated
fresh on your machine. Two ways to get running:

**Option A — quickest:**
1. In Android Studio: `File → New → New Flutter Project → Flutter Application`,
   name it `cafe_management_system`, finish the wizard (this generates all
   the native platform folders for you).
2. Delete the generated `lib/` folder and the generated `pubspec.yaml`.
3. Copy this package's `lib/` folder and `pubspec.yaml` into the new project,
   replacing the generated ones.
4. Run `flutter pub get` (or click "Get dependencies" when Android Studio
   prompts), then pick a device and click ▶ Run.

**Option B — via terminal, if you have the Flutter SDK installed:**
```bash
flutter create cafe_management_system
cd cafe_management_system
# then copy this package's lib/ and pubspec.yaml into place, overwriting
flutter pub get
flutter run
```

Either way, from then on:
1. Install the Flutter & Dart plugins in Android Studio if you haven't
   (Preferences/Settings → Plugins → search "Flutter", install; it pulls in
   the Dart plugin too).
2. Pick a device/emulator from the device dropdown (Android emulator, iOS
   simulator, Chrome, or desktop all work — the UI is responsive to every
   one of them).
3. Click the green ▶ Run button, or run `flutter run` from the terminal.

No API keys, backend, or extra setup is required — everything runs on mock
in-memory data defined in `lib/services/app_data.dart`.

## What's included

- **Landing page**: header, hero, about, menu (₱ pricing), contact footer.
- **Auth flow**: Login (show/hide password, forgot-password dialog) →
  Register → OTP verification (6-digit boxes, countdown, resend, change
  email) → back to Login.
- **Admin side** (sidebar): Dashboard with KPI cards/charts/notifications,
  Reports & Analytics (Sales/Inventory/Payroll/Expenses tabs), Messaging
  (Admin ↔ Employees), Inventory/Kitchen (status badges, low-stock alerts,
  near-expiration → promotion creation), Payroll (editable bonus/deductions,
  mark as paid), POS (cart, discount slider, checkout that deducts
  inventory live), Customer Feedback (star ratings, reply, mark reviewed),
  Procurement (restock flow tied to low stock), Petty Cash (add cash/record
  expense, running balance), User Management (add/disable/archive users),
  Archive (restore or permanently delete, with confirmation dialogs), Admin
  Profile.
- **Employee side** (sidebar): Dashboard, POS (same engine as Admin),
  Kiosk order management (accept → POS → inventory deduction), Inventory
  (read-only), Attendance (RFID/QR scan simulation with countdown + history),
  Payroll (read-only, own record only), Messaging (with Admin), Customer
  Feedback (view-only), Employee Profile.
- **Customer side** (bottom nav / sidebar): Menu/Kiosk (browse, cart, place
  order), My Orders (pending + history), Feedback (star rating + comment
  submission), Profile.
- **Connected flows demonstrated live with mock data**:
  `Kiosk → POS → Inventory → Low Stock Alert`,
  `RFID/QR → Attendance → Payroll`,
  `Customer → Feedback → Admin`,
  `Inventory → Low Stock → Procurement`,
  `Inventory → Near Expiration → Promotion`,
  `Active User → Archive → Restore/Permanently Delete`.
- **Responsive design**: a wide-screen sidebar layout automatically switches
  to a Drawer + bottom NavigationBar on narrow/mobile widths, in the shared
  `AppShell` widget used by all three sides.

## Project structure

```
lib/
├── main.dart                 # App entry point
├── theme/app_theme.dart       # Café color palette & ThemeData
├── models/models.dart         # All data models (User, Product, Order, etc.)
├── services/app_data.dart     # In-memory "backend" — mock data + business logic
├── widgets/shared_widgets.dart# Reusable shell, cards, tables, badges, dialogs
├── screens/
│   ├── landing/                # Public landing page
│   ├── auth/                   # Login, Register, OTP
│   ├── admin/                  # All 10 admin modules + dashboard + profile
│   ├── employee/                # Employee dashboard + modules
│   └── customer/                 # Kiosk, orders, feedback, profile
```

## Wiring up a real backend later

Every mutation (login, checkout, archive, etc.) goes through a single method
on `AppData` in `lib/services/app_data.dart`. To connect Firebase or a REST
API, replace the bodies of those methods with real network/Firestore calls —
the UI layer never touches raw data directly, so screens won't need to
change.
